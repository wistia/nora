**RubyGems checksum cache and package cooldown exemptions** — `/info` bodies are shared by the per-gem checksum in `/versions` and retained in a bounded one-day memory cache. Unchanged entries avoid per-gem S3 reads and upstream revalidation; normal checksum refreshes default to five minutes and exact-name cooldown exemptions use one minute. Replicas coordinate through content-keyed shared objects rather than invalidations. Upstream HTTP cache policy and artifact integrity/curation remain enforced. See `docs/gems-compact-cache.md` for configuration, rollout and storage retention.
